# Защита проекта: Как работает `CompanyImpl`

Это руководство поможет вам уверенно защитить свой проект. Здесь описана логика кода, причины выбора конкретных решений и подробный разбор файла `company_impl.py` по номерам строк.

***

## 1. Основная задача и что такое O(1)?

Согласно заданию, основные методы (`getEmployee`, `hireEmployee`, `fireEmployee`, `getEmployeesByDepartment`) должны работать за время **O(1)**.

* **Что это значит?** O(1) (константное время) означает, что скорость работы метода **не зависит** от количества сотрудников. Независимо от того, работает в компании 10 человек или 1 миллион, программа находит нужного сотрудника мгновенно.

* **Как этого добиться?** Мы **не можем** использовать списки (`list`) для поиска, так как поиск по списку занимает время O(n) (нужно перебрать каждого). Поэтому мы использовали **Словари (`dict`)** и **Множества (`set`)**. Поиск по ключу в словаре Python происходит мгновенно (благодаря алгоритму хеширования).

## 2. Разбор файла по строкам

### Импорты (Строки 1-3)

Python

```
1: from company import Company
2: from employee import Employee
3: from datetime import datetime, date
```

* **Логика:** Мы импортируем абстрактный класс `Company` (который мы реализуем), класс `Employee` (данные сотрудника) и функции даты (для расчета возраста).

### Пользовательские типы исключений (Строки 4-11)

Python

```
4: class EmployeeAlreadyExistsError(Exception):
5:     """Исключение, возникающее при попытке нанять уже существующего сотрудника"""
6:     pass
7:
8: class EmployeeNotFoundError(Exception):
9:     """Исключение, возникающее при попытке найти/уволить несуществующего сотрудника"""
10:     pass
```

* **Логика:** Мы создаем собственные типы ошибок. Если кто-то попытается добавить уже существующего сотрудника или уволить того, кого нет — программа выдаст эти понятные ошибки, а не "вылетит" с неясной системной ошибкой.

### Класс и конструктор (Строки 12-17)

Python

```
12: class CompanyImpl(Company):
13:     def __init__(self):
14:         # Словарь для быстрого поиска сотрудника по id: {id: Employee}
15:         self._employees = {}
16:         # Словарь для быстрого поиска по отделу: {department: set(Employee)}
17:         self._departments = {}
```

* **Логика:** В конструкторе `__init__` мы подготавливаем "фундамент" для скорости O(1).

  * `self._employees` — словарь, где **ключ** — это `id` сотрудника, а **значение** — сам объект сотрудника. Это позволяет мгновенно найти любого человека по его ID.

  * `self._departments` — словарь, где **ключ** — название отдела (например, "IT"), а **значение** — **множество** (`set`) сотрудников этого отдела.

### Метод hireEmployee (Найм) (Строки 18-28)

Python

```
18:     def hireEmployee(self, empl: Employee):
19:         if empl.id in self._employees:
20:             raise EmployeeAlreadyExistsError(f"Employee with id {empl.id} already exists")
21:             
22:         self._employees[empl.id] = empl
23:         
24:         if empl.department not in self._departments:
25:             self._departments[empl.department] = set()
26:             
27:         self._departments[empl.department].add(empl)
```

* **Логика:** Чтобы нанять сотрудника за O(1), мы делаем 3 вещи:

  1. Проверяем, не существует ли он уже (строки 19-20).

  2. Помещаем его в словарь по `id` (строка 22).

  3. Добавляем его в словарь отделов (строки 24-27). Если отдела еще не существовало, мы сначала создаем пустое множество (`set()`), а затем добавляем туда сотрудника.

### Метод fireEmployee (Увольнение) (Строки 29-41)

Python

```
29:     def fireEmployee(self, id: str):
30:         if id not in self._employees:
31:             raise EmployeeNotFoundError(f"Employee with id {id} not found")
32:             
33:         empl = self._employees[id]
34:         del self._employees[id]
35:         self._departments[empl.department].remove(empl)
36:         
37:         # Очистка пустого отдела
38:         if not self._departments[empl.department]:
39:             del self._departments[empl.department]
40:         
41:         return empl
```

* **Логика:** Опять же, для соблюдения O(1):

  1. Проверяем наличие сотрудника (строки 30-31).

  2. Сохраняем его во временную переменную `empl`, чтобы знать, из какого отдела его удалять (строка 33).

  3. Удаляем его из основного словаря `self._employees` (строка 34).

  4. Заходим в его отдел в `self._departments` и удаляем его из множества (строка 35). Удаление из множества также работает за O(1).

  5. Если отдел стал пустым, удаляем его для экономии памяти (строки 38-39).

  6. Возвращаем объект уволенного сотрудника, как того требует интерфейс (строка 41).

### Быстрые запросы (Строки 42-46, 60-63)

Python

```
42:     def getAllEmployees(self):
43:         return self._employees.values()
44:         
45:     def getEmployeesByDepartment(self, department: str):
46:         return self._departments.get(department, set()).copy()
```

Python

```
60:     def getEmployee(self, id: str) -> Employee:
61:         if id not in self._employees:
62:             raise EmployeeNotFoundError(f"Employee with id {id} not found")
63:         return self._employees[id]
```

* **Логика:**

  * `getAllEmployees`: просто возвращает все значения из словаря `_employees`.

  * `getEmployeesByDepartment`: мгновенно получает нужный отдел из словаря (O(1)). Если отдела нет — возвращает пустое множество `set()`. **Важно:** Мы возвращаем `.copy()`, чтобы внешний код не мог случайно изменить наши внутренние данные.

  * `getEmployee`: мгновенно получает сотрудника по ID из словаря `_employees` (O(1)).

### Фильтрация (Строки 48-60)

Для фильтрации по зарплате и возрасту O(1) не требовалось, поэтому мы перебираем всех сотрудников (сложность O(n)).

Python

```
48:     def getEmployeesBySalary(self, fromSalary: int, toSalary: int):
49:         return [empl for empl in self._employees.values() if fromSalary <= empl.salary <= toSalary]
```

* **Логика:** Мы используем "list comprehension" (генератор списков) — это быстрый и элегантный способ отфильтровать список в одну строку. Мы оставляем только тех, чья зарплата (`salary`) попадает в диапазон.

Python

```
52:     def getEmployeesByAge(self, fromAge: int, toAge: int):
53:         today = date.today()
54:         result = []
55:         for empl in self._employees.values():
56:             birthdate = datetime.strptime(empl.birthdate, "%Y-%m-%d").date()
57:             age = today.year - birthdate.year - ((today.month, today.day) < (birthdate.month, birthdate.day))
58:             if fromAge <= age <= toAge:
59:                 result.append(empl)
60:         return result
```

* **Логика расчета возраста:**

  * Строка 56: Превращаем строку вида `"2000-01-01"` в настоящий объект даты.

  * Строка 57 (хитрый расчет возраста): Мы вычитаем год рождения из текущего года. Логическое выражение `((today.month, today.day) < (birthdate.month, birthdate.day))` проверяет, прошел ли уже день рождения в этом году. Если день рождения еще не наступил, выражение дает `True` (что в Python равно `1`), и мы вычитаем один год. Это самый надежный способ посчитать полные годы.

## 3. Как все протестировать

Запустите эти команды в терминале, чтобы убедиться, что все методы работают правильно:

### Тест 1: Базовый найм и получение

Bash

```
python -c "
from company_impl import CompanyImpl
from employee import Employee

c = CompanyImpl()
e = Employee('1', 'John', '1990-01-01', 'IT', 50000)
c.hireEmployee(e)

result = c.getEmployee('1')
print(f'✓ getEmployee работает: {result.name}')
"
```

### Тест 2: Поиск по отделу за O(1)

Bash

```
python -c "
from company_impl import CompanyImpl
from employee import Employee

c = CompanyImpl()
e1 = Employee('1', 'John', '1990-01-01', 'IT', 50000)
e2 = Employee('2', 'Jane', '1991-01-01', 'IT', 60000)
c.hireEmployee(e1)
c.hireEmployee(e2)

dept_employees = c.getEmployeesByDepartment('IT')
print(f'✓ getEmployeesByDepartment работает: {len(dept_employees)} сотрудников в IT')
"
```

### Тест 3: Все тесты одной командой

Bash

```
python -c "
from company_impl import CompanyImpl
from employee import Employee
from company_impl import EmployeeAlreadyExistsError, EmployeeNotFoundError

print('=== Тестирование CompanyImpl ===')

c = CompanyImpl()
e1 = Employee('1', 'John', '1990-01-01', 'IT', 50000)
e2 = Employee('2', 'Jane', '1985-01-01', 'HR', 70000)
e3 = Employee('3', 'Bob', '1995-01-01', 'IT', 30000)

# Тест 1: Найм
c.hireEmployee(e1)
c.hireEmployee(e2)
c.hireEmployee(e3)
print('1. ✓ hireEmployee работает')

# Тест 2: getEmployee (O(1))
emp = c.getEmployee('1')
assert emp.name == 'John'
print('2. ✓ getEmployee O(1) работает')

# Тест 3: getEmployeesByDepartment (O(1))
it_emps = c.getEmployeesByDepartment('IT')
assert len(it_emps) == 2
print('3. ✓ getEmployeesByDepartment O(1) работает')

# Тест 4: Фильтр по зарплате (O(n))
salary_emps = c.getEmployeesBySalary(40000, 60000)
assert len(salary_emps) == 1
print('4. ✓ getEmployeesBySalary работает')

# Тест 5: Увольнение (O(1))
fired = c.fireEmployee('1')
assert fired.name == 'John'
print('5. ✓ fireEmployee O(1) работает')

print('\n=== Все тесты пройдены! ===')
"
```

## Резюме для преподавателя

Если преподаватель спросит: _"Почему вы использовали словари и множества?"_

**Ваш ответ:** _"Потому что требованием была скорость O(1) для поиска, найма и увольнения. Словари (`dict`) и множества (`set`) в Python основаны на хеш-таблицах, поэтому вставка, удаление и поиск в них выполняются в среднем за константное время O(1), в отличие от списков (`list`), где это заняло бы линейное время O(n)."_
